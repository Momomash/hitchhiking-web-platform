# Самое большое легаси, с которым мы работаем, — веб-платформа

Доклад для **HolyJS 2026 Autumn** (23 октября 2026, кейноут).
Спикер — Мария Кондаурова, BIOCAD. Приглашённый эксперт — Денис Чернов, SM Lab.

Страница доклада: https://holyjs.ru/talks/20011365-the-biggest-legacy-we-work-with-is-the-web-platform/

## О чём доклад

> В эпоху AI и экзистенциального кризиса нелишним будет вспомнить, что самое большое
> легаси, с которым мы работаем, — веб-платформа. Под капотом браузера давно живет не
> просто набор HTML, CSS и JS, а огромная система стандартов, тестов, комитетов и
> компромиссов, которая одновременно держит интероп, двигает дизайн и влияет на бэкенд,
> а теперь еще и интегрируется с AI, но все еще не развалилась.
>
> Поностальгируем и посмотрим, как веб вырос из «просто сайта» в сложную, но удивительно
> живую платформу: от раннего веба и CSS до responsive design, Interop, Web Platform Tests,
> новых Web API и будущих AI-протоколов. В конце мы увидим, что веб — это не только
> технология, но и зеркало наших ожиданий от интерфейсов, устройств и самой жизни.

Сквозная рамка: веб-платформа разбирается как обычный продукт, который вырос, —
от MVP до легаси, которое нельзя переписать.

## Структура

| | Глава | О чём |
|:---|:---|:---|
| 0 | Пролог. Продукт, который вырос | как растёт любой продукт — и как тот же путь прошёл веб |
| 1 | MVP, который оказался слишком успешным | Бернерс-Ли, «невинный» веб, Space Jam, Million Dollar Homepage |
| 2 | Требования росли — веб отвечал | AJAX → SPA → мобильность → PWA → SSR: каждый скачок как накопившееся давление требований |
| 3 | Веб переписал не только фронтенд | две арки: дизайн (документ → правила) и бэкенд (страницы → данные → edge) |
| 4 | У мирового продукта нет одного владельца | спецификации, браузерные войны, модульность-протезы, Interop и WPT |
| 5 | Цена успеха — legacy | User-Agent, site patches, легаси, записанное в стандарт, и почему это не ругательство |
| 6 | Новый пользователь: агент | Prompt API, `position: negative`, каким будет следующий веб |

## Запуск

```bash
npm install
npm run dev      # дев-сервер с презентацией, открывает браузер
npm run build    # статическая сборка в dist/
npm run export   # экспорт в PDF
```

Спикерские заметки — в presenter mode: `/presenter` на дев-сервере.

## Тема

Своя тема в `theme/` — веб-платформа как старая операционная система: окна,
статус-бары, режимы совместимости и предупреждения, которые нельзя удалить.
Гамма — Windows XP «Luna» Silver. Подробности, палитра и список компонентов —
в [theme/README.md](theme/README.md).

Двенадцать лейаутов (`cover`, `section`, `default`, `statement`, `two-column`,
`timeline`, `chart-full`, `image-full`, `image-left`, `image-right`, `image-top`,
`end`) и компоненты в духе оконного ретро:
`SystemWindow`, `OsTitleBar`, `OsStatusBar`, `OsUrlBar`, `BrowserFrame`,
`WarningDialog`, `LegacySticker`, `Screenshot`, `MediaPlayer`, `RequirementCard`,
`AgentPrompt`, `OsGroupBox`, `FigCaption`.

## Конвенции слайдов

- **`sectionNumber`** во фронтматтере — сквозной номер вида `4-17` (глава-слайд);
  разделители глав несут номер главы строкой: `'4'`. Выводится в хроме слайда,
  помогает ориентироваться и на прогоне, и в обсуждении правок.
- **`tone`** ставится на все слайды главы разом, включая разделитель: `origin`,
  `growth`, `craft`, `standards`, `legacy`, `agent`. Имя тона — по смыслу главы,
  а не по цвету.
- **Спикерские заметки** — в `<!-- -->` под слайдом. Заметка не пересказывает слайд,
  а добавляет к нему слой: то, что говорится голосом и чего на экране нет.
- **`[click]`** в заметке отмечает момент, на котором нужно кликнуть. Маркеров
  не больше, чем кликов на слайде.
